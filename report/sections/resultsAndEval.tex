\section{Results and Evaluation}
\label{sec:results}

This chapter reports outcomes against the three-axis evaluation
plan committed in Section~\ref{sec:vvt}.

\subsection{Evaluation design and suitability of approach}
\label{sec:eval-design}

The suite is assessed against the three Introduction-stated
claims rather than a single global metric: \emph{coverage} (OWASP
breadth and modern-stack diversity), \emph{integrity} (the
per-user HMAC flag layer resists flag copying and LLM-assisted
solving under deliberate attack), and \emph{engineering rigour}
(intended exploit paths survive code change). Three tracks map
onto these claims. \textbf{Automated regression} supplies an
objective solvability ground truth, removing the
solver-skill confound Meinsma et al.~\cite{Meinsma2022} identify
in platform-log evaluation. An \textbf{LLM solvability trial}
tests the integrity claim directly: a five-model panel
(\texttt{claude-sonnet-4-6}, \texttt{claude-haiku-4-5},
\texttt{gpt-5-mini}, \texttt{gemini-2.5-pro},
\texttt{gemini-2.5-flash}) attempts every challenge from the
same curated public surface a student would see, under both a
passive single-turn condition and a 15-turn agentic condition
with a fail-closed sandboxed tool surface, plus a no-stack
\textit{cold-probe} as an integrity test against
training-data leakage. A flag is recorded as solved only when
the submitted string is byte-identical to the HMAC-derived
value for the deployment salt and test user, so a
methodologically correct but hallucinated flag is a
categorical failure. A \textbf{human
walkthrough} captures the process evidence absent from solver
counts: time-to-flag, AI-tool reliance, confidence shift,
enjoyment and learning Likerts, and free-text feedback on
method, issues, and breadcrumb effectiveness.

\textbf{Why an LLM track at all.} The motivation is a
pedagogical-integrity question, not benchmark curiosity.
Capable LLMs are freely available to students, and a graded
module solvable by pasting the brief into a chat window
substitutes prompting skill for the security learning the
module is designed to cultivate. The trial operationalises
that risk: if an unaided model can recover the byte-correct
per-user flag from the same curated public surface a student
sees, flag possession is no longer evidence of methodology. A
``human plus LLM'' joint condition would outperform the
unaided panel --- a human relay removes the 15-turn cap, the
safety refusals, and the doc-pack-only context --- but the
design objective is learning, not maximum solve rate, so the
unaided-LLM column is the control that distinguishes ``the
suite remains solvable'' from ``the suite remains
learnable.'' The joint condition is identified as further
work in Section~\ref{sec:conclusion}.

The LLM trial artefacts are pre-committed: protocol
(\texttt{Evaluation/llm/PROTOCOL.md}), success criterion
(\texttt{PLAN.md} \S5), failure rubric (\texttt{RUBRIC.md}),
prompt SHA-256 hashes (\texttt{PROMPT\_HASHES.txt}), per-flag
regexes (\texttt{flag\_regexes.json}) and expected flag map
(\texttt{expected\_flags.json}) all live under
\texttt{Evaluation/llm/} ahead of any scoring run. The
byte-match success criterion turns the integrity question from a
claim into a measurement: any submission that is not byte-equal
to the expected HMAC for the test user is a categorical failure,
regardless of whether the methodology was correct.

\subsection{Results}
\label{sec:eval-results}

\subsubsection{Automated regression}
\label{sec:eval-automated}

Regression is exercised at three layers, each with a single
command-line entry point.
\textbf{Unit and integration suites} ship with every
challenge in its native framework (Section~\ref{sec:vvt});
a cross-stack runner at \texttt{CTFs/run-all-tests.sh}
iterates the nine commands, prints a pass/fail/duration
table, and exits non-zero on any failure, with a
\texttt{-{-}quick} switch that skips the two cold-build
suites (CTF6 cargo, CTF9 Maven). \textbf{Continuous
integration} pins the same matrix in
\texttt{.github/workflows/tests.yml}, which fans out to
nine parallel jobs (one per CTF, on
\texttt{ubuntu-latest} with each toolchain pre-installed)
on every push and pull request to \texttt{main}; this is
the gate behind ``contracts green across the corpus'' in
the engineering-rigour claim.
\textbf{End-to-end exploit scripts} live under
\texttt{CTFs/e2e/}; cumulative source is 1\,454 lines
across nine scripts plus a 67-line shared
\texttt{conftest.py} providing \texttt{wait\_for\_service}
(\texttt{conftest.py:13}) and \texttt{load\_credentials}
(\texttt{conftest.py:30}) helpers.
Table~\ref{tab:e2e-coverage} summarises coverage: all 23
flags in the suite are asserted, with CTF8's third flag
fixture exercised via a separate contract assertion rather
than the e2e intended chain. Test discovery reports 60
collected node IDs
(\texttt{e2e/.pytest\_cache/v/cache/nodeids}); the
\texttt{README.md} headline of ``56 tests'' counts only the
named flag-and-contract assertions.

\subsubsection{LLM solvability trial}
\label{sec:eval-llm}

\textbf{Trial design.} The LLM track is driven by an agentic
harness committed under \texttt{Evaluation/llm/} (113 unit
tests). A \texttt{Guard} module enforces a fail-closed
allow-list: filesystem reads restricted to
\texttt{prompts/}, \texttt{doc-pack/}, the current run's
output directory, and read-only \texttt{expected\_flags.json}
and \texttt{flag\_regexes.json}; HTTP restricted to
\texttt{http://localhost:<port>} for the current CTF's
declared ports. A \textit{shell} tool exposes an Alpine
scratch container (\texttt{--memory 256m --cpus 1}, 30\,s
timeout); a \textit{submit\_flag} tool records candidate
strings; \textit{give\_up} terminates the run. Conditions
are \textit{passive} (one user turn, doc pack plus a login-page
HTML snapshot, no tools), \textit{agentic} (system + user
prompts, full tool surface, capped at \textbf{15 turns}),
and \textit{cold-probe} (doc pack only, no stack, no tools ---
the integrity probe against training-data leakage). Two
further conditions (\textit{pilot}, \textit{null-prompt})
gate trial readiness rather than contribute to the headline
tables. Prompts are SHA-pinned in \texttt{PROMPT\_HASHES.txt};
marker-facing material (the \texttt{CTF Flags} tables, the
\texttt{Challenge Overview} kill-chain, references to
\texttt{SOLUTIONS.md}) is stripped from each doc pack before
the model sees it (\texttt{doc-pack/CURATION\_LOG.md}).
Per-flag passes require all three of (i) regex-shape match,
(ii) \emph{byte-identity} with the demo-account HMAC value
in \texttt{expected\_flags.json}, and (iii) appearance of
that string inside \texttt{submit\_flag} arguments or an HTTP
response body in the same run. A well-formed but hallucinated
flag is therefore a categorical failure, not a near-miss.

\textbf{Run matrix and budget.} Table~\ref{tab:llm-matrix}
records the executed matrix: 127 paid runs across five
phases, yielding 332 flag-slot observations for a total spend
of USD\,5.25, well within the \pounds20 hard cap. Two
deliberate budget concessions are disclosed openly rather
than retro-fitted to the plan: \texttt{claude-haiku-4-5}
was dropped from the primary phase after Sonnet exhausted
the Anthropic per-vendor credit (cold-probe data retained),
and the originally-specified \texttt{gpt-5} spot-check was
skipped to hold remaining vendor credit back for analysis-phase
contingencies. \texttt{PLAN.md} carries the corresponding
revision history (panel expansion 2026-04-12, single-seed cut
2026-04-27, demo-account simplification 2026-04-28).

\textbf{RQ-L3 --- integrity (the headline finding).} Two
independent integrity controls converge on the same answer.
First, the cold-probe phase across the 5-model panel produced
\textbf{0/121 byte-matches}, despite roughly 37\,\% of
cold-probe failures being coded \texttt{methodology-correct,
flag-absent} --- the model named the right technique but had
no surface from which to derive an HMAC tail. Second, across
all 325 failed-flag rows in the trial, \textbf{0 were coded
\texttt{methodology-correct, flag-hallucinated}}: not a
single model fabricated even a regex-shape guess that
byte-matched a real flag. The harness recorded only one
\texttt{submit\_flag} call across all 127 paid runs (the
Gemini 2.5 Flash CTF9 success); models in agentic runs
preferentially \texttt{give\_up} (96 runs) or truncate
(30 runs) rather than commit to an unverified string. The
HMAC-tail construction does what the methodology claimed:
it distinguishes capability from regurgitation, even when the
methodology is correctly named.

\textbf{RQ-L1 / RQ-L2 --- difficulty stratification and
scaffolding.} The pass-rate tables corroborate the assigned
difficulty bands at the LLM level. Every Easy and Medium
agentic cell is at chance under the 15-turn cap save Sonnet's
single CTF1 success; the Hard tail is at chance for Sonnet,
Pro and gpt-5-mini and is swept once by Flash on CTF9. The
agentic-minus-passive scaffolding delta is sparse: only
\textbf{two} of the $9 \times 4 = 36$ cell pairs flipped from
0 to a non-zero pass rate (CTF1/Sonnet, CTF9/Gemini Flash).
The remaining 34 cell pairs stayed at 0. Truncation absorbed
most of the agentic budget --- 75 of 90 agentic flag-slots
failed, all 75 by hitting the 15-turn cap, and CTF5 (multi-stage
SSTI) plus CTF9 (six-stage chain) account for 16 and 18
truncations respectively. The cell-pair flips are
idiosyncratic rather than systematic; under the diagnostic
$n=1$ framing this is the expected pattern, but the practical
implication for a budget-bounded re-run is that the 15-turn
cap is the dominant tunable, not the model identity.

\textbf{Failure-mode profile.} Table~\ref{tab:llm-subcodes}
gives the sub-code distribution for the primary phase
($n = 204$ failed-flag rows) under the rubric in
\texttt{Evaluation/llm/RUBRIC.md}. The two-thirds majority

runs that ran out the chain without producing a flag (30\,\%);
methodology-wrong runs are 21\,\%, and partial-but-misnamed

\textbf{Inter-rater reliability --- declared caveat.} A 20\,\%
double-rate sample (\textit{n}\,=\,65 of 325 rows,
deterministic seed \texttt{20260428}) yielded Cohen's
$\kappa$\,=\,\textbf{0.959} (raw agreement
63/65)~\cite{Cohen1960}. The figure is reproduced for
completeness but should not be over-claimed: the secondary
rater is the same author applying a stricter
``core-mechanism'' keyword threshold to the same summaries
(\texttt{scripts/double\_rate.py::CORE\_MECHANISM}), with the
two raters sharing the per-flag ground-truth tables and
disagreeing only on the correct-vs-partial boundary. This is
therefore a \emph{coding stability check} rather than a
genuinely blind IRR figure; time and budget pressure ruled
out a supervisor or peer pass. A blind-secondary revision
would be expected to produce a lower kappa, particularly along
the same boundary on which the two recorded disagreements
fell.

\textbf{RQ-L4 --- qualitative seeds.} Of the two cells that
flipped, the Sonnet 4.6 CTF1 path identified base64 cookie
tampering, re-encoded the role claim, and resubmitted under
the cap, mirroring the unaided human path
(Section~\ref{sec:eval-human}). The Gemini 2.5 Flash CTF9
sweep --- the only multi-flag clean run --- walked all six
stages (actuator chain, \texttt{....//} traversal for the
PEM, HS256 forgery, blind Boolean SQLi, RSA-512 factorisation
with AES-GCM decryption, logfile credential recovery) inside
the 15-turn budget. A non-flagship Gemini solving CTF9
unaided is a strong upper bound on what the suite resists
agentically; that it is the only such sweep across 36 cells
keeps the result idiosyncratic under the diagnostic framing.
CTF5 (SSTI) and CTF6 (SSRF/IMDS) absorbed the bulk of
truncation: models named the correct OWASP class and reached
plausible probes (\texttt{\{\{config\}\}} introspection,
\texttt{169.254.169.254}-shaped requests) but ran out of
turns before the multi-step pivot. CTF4 stalled on
diagnosing the admin-bot polling delay rather than completing
the XSS exfiltration.

\textbf{Calibration against an unbounded manual pass.} An
exploratory manual pass under \texttt{Evaluation/llm/manual/}
relayed tool output by hand to GPT-5.3 with no turn cap. It
is calibration data, not part of the primary tables, but is
useful as an upper bound under unlimited budget: eight of
nine CTFs solved fully in 5--30 turns each. CTF9 exhibited
a separate failure mode --- GPT-5.3 refused thirty-plus
times under what appeared to be a safety heuristic on the
clinical-research narrative --- recorded as a behaviour
observation distinct from any agentic-trial failure code.
For internal validity, every primary-phase 0-pass cell on a
CTF GPT-5.3 solves manually is best read as ``the 15-turn
cap absorbed this run,'' not ``the technique was beyond the
panel.''

\textbf{What the trial does not establish.} Three deliberate
non-claims: with one seed per cell, within-cell variance is
unestimated and CIs are reported as diagnostics, not
inference; the panel excludes flagship-tier models (Opus,
GPT-5, Gemini Ultra) at primary scale, priced at roughly
USD\,9 per nine-CTF run versus the \pounds20 hard cap; and no
retrieval-augmented or memory-equipped agent class
(\texttt{CTFAgent}-style~\cite{ji2025}) was evaluated. The
natural successor study is identified as further work in
Section~\ref{sec:conclusion}.

\subsubsection{Human walkthrough}
\label{sec:eval-human}

Four participants ($n=4$) drawn from the Durham CS UG/MEng
cohort completed the protocol fixed in
\texttt{Evaluation/human/PLAN.md}. Each participant attempted a
single CTF spanning the difficulty range (one Easy, one Medium,
two Hard), with the post-CTF instrument capturing
solve outcome, time-to-flag, AI-tool use, confidence shift, an
enjoyment Likert (1--10), a learning Likert (1--10), and free-
text on method, issues encountered, aspects that went well, and
suggested improvements. The achieved $n$ is below the target
($n=6$--$10$, \texttt{PLAN.md:12}); the study is treated as a
qualitative triangulation rather than a powered inferential
study, and a Durham CS low-risk ethics form was completed prior
to the first session. The post-CTF survey did not include a
NASA-TLX workload battery in the form distributed to
participants; per-task workload analysis is identified as
further work.

Three observations follow from the small sample.
\textbf{(i) Difficulty ordering corroborated.} Time-to-flag and
unaided/assisted status track the assigned difficulty band:
the Easy CTF1 was solved unaided in 20 minutes by the
least-experienced participant (self-reported prior CTF
experience 1/10, zero prior CTFs); the Medium CTF3 was solved
fully (2/2 flags) with AI assistance in 25 minutes; the two
Hard challenges were partial recoveries (CTF5 3/4 in 40
minutes, CTF9 4/6 in 80 minutes), both with AI assistance and
both by experienced participants (3/10 and 7/10 self-reported
prior CTF experience).
\textbf{(ii) Enjoyment is high across the suite, but learning
ratings dip on the AI-assisted middle band.} All four
participants rated enjoyment 8--10/10. Learning ratings
clustered higher at the extremes (10/10 on CTF1 unaided,
9/10 on CTF9 most-stretched) and lower on the AI-assisted
Medium and Hard middle (6/10 on CTF3, 7/10 on CTF5). The
qualitative responses suggest the dip is not a fault of
challenge depth but of \emph{breadcrumb specificity}: CTF3 and
CTF5 reviewers each named hints they wanted ``more structured''
or ``clearer direction'' for early-game recon, suggesting AI
tools partly substituted for breadcrumbing the suite did not
supply directly.
\textbf{(iii) Free-text identified actionable structural and
silent-data issues, all of which were resolved before
submission.} The CTF5 reviewer flagged that flags~3 and~4
shared a backing file (\texttt{/app/secret/flag.txt}) so an
RCE on \texttt{v1} rendered the WAF-bypass flag~3 trivially
skippable; this was fixed by separating the two flags onto
distinct files and gating flag~3 retrieval through the
\texttt{v2} WAF-protected path. The CTF9 reviewer reported
two silent data-seeding failures (an unresolved
\texttt{\{\{PLAYER\_FLAG2\}\}} template in
\texttt{application.properties}, and an empty
\texttt{flag\_value} for \texttt{flag\_index=4}) that returned
empty-format flags rather than failing closed; both were
fixed in the seeding pipeline so that every per-user flag is
populated at startup and a startup health-check now refuses
to bring the stack up if any expected flag is absent. The
CTF9 path-traversal ``god-mode shortcut'' (whereby
\texttt{/api/files/download?name=} accepted absolute paths
with no base-path restriction, allowing
\texttt{/app/seed/flags.json} to dump every flag) was
restricted to a whitelisted set of intended-solve paths,
preserving the legitimate JWT public-key and config reads
required by the chain. The CTF9 vault file
(\texttt{classified-trial-results-2024-q2.enc}) inaccessibility
was traced to a base-path mismatch and corrected. Each fix
is recorded against the relevant \textit{Post-Design Audit}
appendix.

The breadcrumbs cited as ``the artefact that moved me forward''
in free text were Rachel's security memo (CTF9), the in-page
HTML source comments and \texttt{/static/CHANGELOG.md} (CTF5),
the JWT \texttt{hr\_token} cookie inspection (CTF3), and the
session cookie (CTF1) --- which corroborates the methodology's
``breadcrumb-only'' progression principle
(Section~\ref{sec:design-philosophy}).

\subsubsection{Difficulty calibration}
\label{sec:eval-difficulty}

Difficulty bands (Easy/Medium/Hard) were assigned at design
time from a heuristic combination of stack count, flag count,
and intended-chain depth (Section~\ref{sec:methodology}); they
were not validated against an instrument. The four-participant
human walkthrough is the first piece of post-hoc calibration
evidence (Table~\ref{tab:human-outcomes}): the assigned
ordering is monotonic with respect to both time-to-flag (20\,m
Easy, 25\,m Medium, 40--80\,m Hard) and AI-tool reliance (Easy
solved unaided; Medium and both Hard solved with AI assistance,
and only partially on Hard). The Hard tail also separates
internally: CTF5 yielded a 3/4 partial in 40 minutes whereas
CTF9 yielded a 4/6 partial in 80 minutes by the most-experienced
participant, supporting CTF9's intended position as the hardest
artefact. A larger sample is needed to estimate variance and
confirm tier boundaries; the executed LLM trial
(Section~\ref{sec:eval-llm}) provides the second calibration
estimator and is monotonic in the same direction --- agentic
pass rates are at chance for Easy and Medium under the
15-turn cap save a single Sonnet success on CTF1, and the
sole multi-flag clean sweep is on a Hard challenge (CTF9,
Gemini 2.5 Flash 6/6).

\subsection{Implementation issues and resolutions}
\label{sec:eval-impl}

Five issues were material to the evaluation. The e2e
harness's initial \texttt{time.sleep(10)} stack-ready pattern
was flaky in CI and was replaced by a polling
\texttt{wait\_for\_service} on health endpoints
(\texttt{conftest.py:13}, 60\,s deadline, 2\,s interval).
CTF3's pre-individualisation
\texttt{test\_encryption\_key\_in\_bundle} assertion was
sensitive to Vite bundle chunking and was refactored in
commit \texttt{4d92bb35} into two narrower successor tests,
both in the current gating set. Four vendor-specific bugs
were patched mid-trial in
\texttt{Evaluation/llm/lib/models.py}: an OpenAI \texttt{gpt-5}
temperature constraint, a Gemini
\texttt{additionalProperties} schema rejection, an Anthropic
429 envelope (exponential backoff, 60\,s ceiling), and a
Gemini 503 backoff (capped at three attempts); none
re-occurred after patching, so no row is coded
\texttt{harness-error}. The 15-turn agentic cap was retained
for budget parity but became the dominant failure mode (75 of
90 agentic flag-slots), with CTF5 and CTF9 absorbing the
bulk; a longer cap is the single highest-leverage parameter
for a rerun. Two budget concessions were taken and disclosed
rather than retro-fitted: \texttt{claude-haiku-4-5} was
dropped from the primary phase after Sonnet exhausted
Anthropic credit (cold-probe data retained), and the
\texttt{gpt-5} spot-check was skipped. The per-challenge
\textit{Post-Design Audit} appendices record audit cycles
that fixed unintended paths during development; CTF4
accumulated the most extensive trail (eleven findings, in a
separate \texttt{UNINTENDED\_vulnerabilities.md}).

\subsection{Strengths, limitations and threats to validity}
\label{sec:eval-limits}

\textbf{Strengths.} Every challenge has an executable
intended-exploit assertion, strictly stronger than a
natural-language solution guide. The HMAC flag layer turns
integrity from a stated property into a falsifiable
measurement, with direct empirical support (0/121 cold-probe
byte-matches and 0/325 hallucinated-flag rows). Three tracks
triangulate on the same artefact: e2e exploit-as-a-test for
ground truth, a 5-model agentic LLM harness with cold-probe
for integrity, and a structured human walkthrough for process
evidence. The standardised \textit{Post-Design Audit} record
documents unintended-path discovery and resolution in a
comparable schema across the suite.

\textbf{LLM-trial limitations.} The trial runs $n=1$ per
(model, CTF, condition) cell by design and budget; CIs are
reported as diagnostics, not inference. The panel excludes
flagship-tier models (Opus, GPT-5, Gemini Ultra) at primary
scale, priced at $\sim$USD\,9 per nine-CTF run versus the
\pounds20 cap. The 15-turn cap absorbs the agentic budget
(75 of 90 truncations, mostly on CTF5/6/9), so
``methodology correct, flag absent'' is not always a
capability claim --- the manual GPT-5.3 pass solves eight of
nine unbounded. The reported $\kappa = 0.959$ is a
same-author coding stability check, not a blind IRR; a blind
pass would likely produce a lower kappa on the
correct-vs-partial boundary. No retrieval-augmented
(\texttt{CTFAgent}-style~\cite{ji2025}) condition was
evaluated. GPT-5.3's CTF9 over-refusal is recorded
separately as a behaviour observation.

\textbf{Human-track and design limitations.} $n=4$ is below
the target range ($n=6$--$10$), single-institution, with
single-participant per-CTF coverage; effect sizes are
descriptive only. The fielded survey captured outcome, time,
AI-tool use, confidence shift, enjoyment/learning Likerts and
free text but not the NASA-TLX workload battery. The
``learning gain over status quo'' claim is made by
construction against the fixed-VM literature critique, not by
a randomised between-groups comparison against the COMP2211
baseline. The human protocol is fixed but the analysis plan
was not formally locked.

\textbf{Architectural caveats.} Integrity depends on the
deployment salt remaining secret; a shared-host filesystem
read collapses the HMAC layer to a deterministic function of
public inputs. Automated tests assert intended exploits only;
the \textit{Post-Design Audit} record is the only systematic
search for alternative paths, and an undiscovered bypass
cannot be ruled out. Likert items are subjective; where
free-text and behavioural evidence diverge, the behavioural
reading is preferred.

\subsection{Reflection on software engineering process and project organisation}
\label{sec:eval-se}

The suite was delivered under a three-phase plan recorded in
\texttt{CHANGELOG.md}: challenge-by-challenge build, stack
isolation and orchestration, and evaluation. Building the
evaluation harness before the LLM and human trials forced the
executable success criterion to be agreed in code before it
could be argued in prose. The principal organisational risk
was over-scoping: nine challenges plus three evaluation
tracks is a large surface, and the LLM panel was scoped to a
\pounds20 envelope. Two cost-control levers were pulled and
recorded as PLAN.md revisions rather than retro-fitted: cutting
\texttt{PRIMARY\_SEEDS} from $(1,2)$ to $(1,)$ on 2026-04-27
and dropping \texttt{claude-haiku-4-5} from the primary phase
on 2026-04-28. The trial delivered against the revised scope
(127 paid runs, 332 flag-slot observations, USD\,5.25 spend,
113 unit tests green). If a single decision were revisited,
it would be to ring-fence an additional envelope earlier ---
roughly an order of magnitude over what was spent --- to
admit a multi-seed flagship column and a longer turn cap.
The harness is budget-replayable from the committed artefacts,
so the rerun is an analysis-phase decision, not a
re-engineering one.

\subsection{Summary of findings}
\label{sec:eval-summary}

Read against the three project claims:
(a) \emph{Coverage} is supported --- all 23 flags across nine
CTFs are asserted (Table~\ref{tab:e2e-coverage}) and the
suite spans eight 2021 OWASP categories across nine stacks;
(b) \emph{Integrity} is supported by construction \emph{and}
by empirical falsification: 0/121 cold-probe byte-matches
across the 5-model panel, with 0 \texttt{flag-hallucinated}
rows across all 325 failures despite $\sim$37\,\% of
cold-probe failures correctly naming the required technique
(Section~\ref{sec:eval-llm});
(c) \emph{Pedagogical suitability} is partially supported by
the four-participant walkthrough
(Table~\ref{tab:human-outcomes}): difficulty ordering is
monotonic on time-to-flag and AI-tool reliance, enjoyment
clusters 8--10/10, and the breadcrumbs cited as ``the
artefact that moved me forward'' (Rachel's memo, in-page
comments, the JWT \texttt{hr\_token} cookie) corroborate the
breadcrumb-only progression principle.

\subsection{Contributions}
\label{sec:eval-contributions}

Read against the three claims above and the deliverables
ladder of Section~\ref{sec:research-question}, the project
contributes the following artefacts and findings:
\begin{itemize}
    \item a nine-challenge web-exploitation suite covering
          eight of the ten 2021 OWASP categories with three
          distinct injection sub-types and stacks rarely
          represented in educational CTFs (Flask/Jinja2,
          Rust/Actix-web, Go/Gin, Spring Boot, and a
          queue-driven admin-bot React stack), and a
          standardised \textit{Post-Design Audit} record per
          challenge that documents unintended-path discovery
          in a comparable schema;
    \item a deterministic HMAC-SHA256 flag personalisation
          scheme with per-deployment and per-flag-slot salt
          parameterisation, embedded-username attribution,
          and an executed integrity check (0/121 cold-probe
          byte-matches and 0 hallucinated-flag rows across
          325 failure observations);
    \item a container-native distribution model that keeps
          student data strictly out of the image layer, so
          cohort onboarding is a salt rotation rather than a
          rebuild;
    \item an \textit{exploit-as-a-test} end-to-end harness
          (1\,454 LoC across nine CTFs, 56 named flag-and-contract
          assertions) that acts as the ground-truth oracle
          for challenge solvability and is wired through a
          nine-job CI matrix;
    \item a triangulated evaluation methodology combining
          automated regression, an executed multi-model
          agentic LLM trial committed under
          \texttt{Evaluation/llm/} (113 unit tests, SHA-pinned
          prompts, run matrix, expected-flag map), and a
          structured human walkthrough; and
    \item a reusable artefact set (challenge sources,
          generation layer, e2e harness, LLM harness,
          per-challenge audits, write-up source for the
          evaluation chapter) released as a single
          repository so that any of the above can be
          replayed or extended without further engineering.
\end{itemize}
