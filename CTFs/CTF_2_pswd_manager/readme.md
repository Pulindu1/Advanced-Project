# CTF 2 -- Password Manager

A password manager web application where the goal is to exploit JWT vulnerabilities to steal another user's stored credentials and retrieve the flag.

**Stack:** Node.js (Express) backend, React + Vite frontend

---

## Quick Start (Docker -- recommended)

Requires [Docker Desktop](https://www.docker.com/products/docker-desktop/).

### 1. Generate credentials

```bash
cd CTFs/challenge-generation
node chgen_ctf2.js abcd12 efgh34 ijkl56
```

This creates `CTFs/CTF_2_pswd_manager/flags.json` and `CTFs/CTF_2_pswd_manager/credentials.json`.

### 2. Start the application

```bash
cd CTFs/CTF_2_pswd_manager
docker compose up --build
```

- Frontend: http://localhost:5173
- API: http://localhost:4000

Log in with any username and password from `credentials.json`.

To stop: `docker compose down`
To reset to a clean state (wipes all users/vaults): `docker compose down -v && docker compose up --build`

### Running without Docker (development)

Requires Node.js 16+.

```bash
cd CTFs/CTF_2_pswd_manager
npm install

# Set paths for local development
export FLAGS_PATH=./flags.json
export CREDS_PATH=./credentials.json

# Terminal 1 -- backend API
node server/index.js

# Terminal 2 -- frontend (Vite dev server)
npm run dev
```

Frontend is usually at http://localhost:5173 or :5174.

## CTF Flags

| Flag | Difficulty | Technique |
|------|-----------|-----------|
| 1 | Medium | PoW solve, JWT secret disclosure, JWT forgery, IDOR |

**Flag count:** 1 per user
**Flag format:** `durham-pm{<hash>_<username>}`

---

## Features

- **User Authentication** -- Register and login (username format: 4 letters + 2 digits, e.g. `abcd12`)
- **My Vault** -- Store and manage credentials with password masking
- **Team Members** -- View all registered users
- **2-Stage CTF Challenge** -- Exploit a weak JWT secret to access another user's vault

---

## CTF Integration

Flags and credentials are generated by `CTFs/challenge-generation/chgen_ctf2.js` and mounted into the container at startup. The server reads these files and seeds user accounts and vault entries automatically.

- `flags.json` -- per-user flag values (HMAC-SHA256 deterministic)
- `credentials.json` -- per-user login passwords (randomly generated)

Each user has a corresponding bot user (`<username>-vault`) whose vault contains the flag. The bot user cannot be logged into directly.
